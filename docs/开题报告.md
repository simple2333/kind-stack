# 项目开题报告与初步方案设计

## KindStack（益栈）—— 捐赠物品的一件一码与透明账本

> **选题议题**：议题二 · 轻量自维护的智能库管 —— 告别"数字表格恐惧"
> **出题小店**：示例二手慈善商店（方向三：捐赠物品的一件一码与透明账本）
> **提交时间**：2026 年 8 月

---

## 一、我们观察到的真实问题

### 1.1 慈善商店的"账目透明"困境

示例二手慈善商店每天收到来自全国的捐赠包裹，小件居多、规格不一、几乎无条码。
走访中发现三个层层递进的真实痛点：

1. **录入靠人海、小件被忽略**：目前只能"大件入账、小件忽略"，大量捐赠物没有进入任何记录，
   善意的"数量"无从谈起。
2. **账目无法对外公开**：即使记录了，也只是店内的纸面/表格账本，居民想查"收了什么、卖了什么"，
   完全无法实现——**公益透明只是一句口号**。
3. **公益信任靠人情**：捐赠人寄出包裹后石沉大海，不知道自己的善意去了哪里、帮到了谁，
   长期缺乏正向反馈，公益参与感流失。

### 1.2 为什么传统方案行不通

- **重型进销存（ERP）**：为"盈利"设计，需要建 SKU、录条码、管成本，慈善商店用不上也维护不起。
- **通用表格工具**：录入仍是手工劳动，且**账目可随意修改**，不具备公信力。
- **真实区块链**：多组织节点、共识、能耗，对一个社区小店是过度的技术负担。

**核心洞察**：慈善商店要的不是"库存管理系统"，而是一份**可核验、有温度、能公开**的善意账本。

## 二、我们的解决思路：KindStack（益栈）

### 2.1 一句话

> **给每件捐赠物品一个"身份"（一件一码），让"收进来 → 卖出去 → 钱去哪了"全程公开、防篡改、可核验。**

### 2.2 核心闭环

```
收件拆包 → 拍照/语音/文本 AI 识别 → 店长确认 → AI 定价
  → 生成一件一码(QR 标签) → 上架 → 售出/转赠
  → 每一步写入哈希链账本 → 居民扫码/浏览可查 → 捐赠人凭批量码追踪
```

### 2.3 三大特色能力

| 能力 | 解决什么 | 技术实现 |
|---|---|---|
| **一件一码** | 每件物品可追踪、可验证 | 唯一码 `YZ-日期-序号` + QR 标签，公开物品页展示完整旅程 |
| **哈希链透明账本** | 账目防篡改、有公信力 | append-only 记录 + SHA-256 哈希链，公开指纹居民可自行校验 |
| **AI 无感录入** | 告别手工录入、小件也能入账 | 拍照识别(进货单/物品)、语音转写、文本解析三合一 |

### 2.4 借鉴的成熟开源设计（不重复造轮子）

- **若依 RuoYi**（Gitee 48.7k 星）：操作日志 `sys_oper_log`、登录日志 `sys_logininfor` 的设计 → 我们照搬为 `oper_log` / `login_log`
- **InvenTree**（GitHub 7.4k 星）：条码生成器、append-only 追踪流水 → 我们简化为哈希链
- **Snipe-IT**（GitHub 14.8k 星）：资产唯一编号、checkin/checkout 审计 → 映射到物品状态机
- **human-essentials**（GitHub，公益物资银行）：事件溯源库存、捐赠→分发透明流程 → 我们借鉴其"公益建模"
- **tailpos**（GitHub）：offline-first 本地优先 → 为将来弱网/离线录入预留思路

> 全套完整参考见项目 `../references/` 与 `REQUIREMENTS.md`。

## 三、技术方案概要（已实测验证）

| 层 | 选型 | 说明 |
|---|---|---|
| 前端 | Next.js 16 + React 19 + shadcn/ui | 管理端(需登录)+公开端(匿名)一套代码 |
| 数据层 | **Drizzle ORM + SQLite**（预留 MySQL） | 参数化查询防注入；换库只改驱动 |
| 鉴权 | **Better Auth**（email+密码，多账号） | 店长/店员角色；登录日志 |
| 账本 | append-only 哈希链（SHA-256） | 篡改可检测，公开指纹可核验 |
| AI | mimo-v2.6-flash（拍照/语音/文本/定价） | OpenAI 兼容，仅服务端调用 |
| 打码 | bwip-js + 标签模板拖拽编辑器 | QR 尺寸可调、字段可增删 |
| 安全 | zod 输入校验、登录限流、安全响应头、日志脱敏 | 参照 OWASP 与若依 |

### 已完成的实测验证

- ✅ 拍照进货单 → AI 一次识别 6 种文具（含数量/成色/分类）
- ✅ 语音/文本"收到三只马克杯" → 正确解析入库
- ✅ 哈希链防篡改：修改任意记录 → 整链校验失败
- ✅ 一件一码：确认入库自动生成 `YZ-20260822-0001` 等唯一码
- ✅ 登录/操作日志：自动记录操作人、IP、浏览器、耗时
- ✅ 完整浏览器流程：登录 → AI 识别 → 确认入库 → 货架出现 → 账本指纹更新

## 四、价值与可持续性

- **对店主**：告别手工盘账，小件也能入账，账目自动对外公开。
- **对居民**：扫码即查"这件东西从哪来、到哪去"，重建对公益商店的信任。
- **对捐赠人**：凭批量码追踪"我捐的去向"，公益参与感有回报。
- **对社区**：一份经得起核验的善意账本，是社区信任的基础设施。
- **可持续**：SQLite 单文件零运维；AI 按量计费极低；数据归属商店，赛后无需续费即可运行。

## 六、部署与运行

```bash
npm install
cp .env.example .env.local   # 填入 BETTER_AUTH_SECRET / AI_API_KEY
npm run db:push && npm run db:seed
npm run dev                  # http://localhost:3000
```

- 管理端：`/admin/login`（预置店长 `admin@example.com`）
- 公开端：`/`（账本总览）、`/item/[code]`、`/verify`（指纹校验）、`/receipt`（捐赠回执）

详见项目 `README.md`。
