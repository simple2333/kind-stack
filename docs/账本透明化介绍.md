# 益栈透明账本 · 给捐赠人和居民的一封信

> 每一件捐赠，都看得见去向；每一笔记录，都经得起查证。

## 这是什么

「益栈」是一本开在二手慈善商店里的**透明账本**。它记录每一件捐赠物品的完整旅程：

```
收件 → 定价 → 上架 → 售出 / 转赠 / 自留 / 报废
```

这本账不是店长自己说了算，而是用一套叫**哈希链**的技术保护起来，**任何人、任何时候都可以独立核验它有没有被篡改**。

## 一、一件一码

每件捐赠物品入库时，系统会生成一个唯一编号，例如：

```
YZ-20260822-0001
```

- `YZ` 代表「益栈」
- `20260822` 是入库日期
- `0001` 是当天的序号

每个编号对应一个二维码。扫一下，就能看到这件物品的全部信息：它是什么、成色如何、定价多少、现在在哪个环节、中间经历了哪些操作。

## 二、账本记录什么

每次对物品的操作（入库、定价、上架、售出、转赠……）都会在账本上追加一条记录，内容包括：

- 操作类型（例如「售出」）
- 关联的物品编号
- 操作详情（价格、数量、备注等）
- 操作时间
- 一条**记录自己的哈希值**

账本只许追加、不许修改、不许删除。已经写下的内容无法回头改动。

## 三、什么是哈希链

**哈希（Hash）** 是一段很短的「数字指纹」：把任意一段文字交给 SHA-256 算法，会得到一串 64 位的十六进制字符，例如：

```
4f2a...（共 64 位）
```

它的特点是：

1. **同样的内容，永远得到同样的哈希** —— 这让我们可以事后重新计算核对。
2. **内容只要改动一个字符，哈希就完全变样** —— 想偷偷改账，立刻就能被识破。

**哈希链**，就是把每一条记录按「块」串联起来：

```
第 1 条记录的哈希 = 指纹(第 1 条内容)
第 2 条记录的哈希 = 指纹(第 1 条哈希 + 第 2 条内容)
第 3 条记录的哈希 = 指纹(第 2 条哈希 + 第 3 条内容)
……
```

每一条新记录，都「锁住」了之前所有记录。就像一环扣一环的铁链：

- 想改第 5 条记录？它的哈希会变 → 第 6 条对不上 → 第 7 条也对不上……一路错到底。
- 只有把整条链从第 1 条到最新一条**全部重算**，才能骗过人 —— 而那相当于把整本账重写一遍，等于承认自己动了手脚。

## 四、什么是「账本指纹」

哈希链最新一条记录的哈希，就是整本账的**当前指纹（Fingerprint）**，例如：

```
3f9a...（64 位十六进制字符）
```

它可以被理解成这本账的「防伪标识」：

- 指纹 = 最新块哈希 = 前面所有记录的总和校验。
- 任何人只要在**同一时刻**看过商店公布的指纹，之后随时可以回来重算，看指纹还对不对得上。
- 指纹对不上，就说明这本账被动过。

首页和「账本校验」页面都会实时显示当前指纹，并带「复制」按钮，方便你保存后定期对照。

## 五、居民怎么自己核验

三步即可完成：

1. 打开首页，点「账本校验」（`/verify`）。
2. 页面会显示：
   - **账本完整性**：完整 · 多少条记录 · 未被篡改（系统已重算全链自动检测）；
   - **当前账本指纹**：复制保存。
3. 下次再来（或隔几天），再次进入该页面，对比指纹是否一致：
   - 指纹一致 → 账本没被动过；
   - 指纹变了 → 账本发生了**新的合法追加**（新捐赠、新销售），或出现了异常 —— 可向店长核实。

还可以**校验单条记录**：在页面输入账本记录编号，系统会重放该记录的哈希，验证它是否被篡改。

## 六、为什么值得相信

| 疑虑 | 答案 |
|---|---|
| 店长能偷偷改记录吗？ | 记录内容一经写入即被哈希锁定，改动会让整条链校验失败、指纹对不上。 |
| 账本是店长自己造的吗？ | 任何第三方拿到一条记录的原始内容，都可以独立用同一算法重算哈希做对照。 |
| 会不会只展示一半？ | 账本按「编号」对外公开可查，每件物品的全过程都陈列在它的公开页面。 |
| 哈希值看不懂怎么办？ | 你不需要看懂哈希本身，只要会「复制指纹 → 下次对照」，就能完成核验。 |

## 七、小约定

- **账本指纹** = 哈希链最新块的哈希，代表当前账本全貌。
- **一件一码** = 每件物品的唯一编号，扫码直达它的公开页面。
- **哈希链** = 把记录逐条锁定串联的技术，保证「改不掉、藏不住」。
